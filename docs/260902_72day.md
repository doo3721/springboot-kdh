# **MyBatis**

## **1. MyBatis 개요와 SQL 매퍼 패러다임**

### **1.1 SQL 중심 데이터 접근 기술의 발전 흐름과 패러다임**

- 순수 JDBC: 자바 소스코드 내에 SQL 문자열이 직접 하드코딩되고 Connection, PreparedStatement, ResultSet 등 반복적인 자원 획득과 해제 보일러플레이트 코드가 과도하게 발생함.
- Spring JdbcTemplate: 반복적인 자원 관리와 예외 변환을 프레임워크가 자동화했으나, 여전히 복잡하고 긴 SQL 문이 자바 클래스 내부에 문자열 형태로 혼재되어 가독성과 유지보수성이 저하됨.
- MyBatis: 복잡한 SQL 문을 자바 코드로부터 격리하여 독립된 XML 파일(또는 어노테이션)로 분리 관리하고, 실행 결과를 자바 객체(Record, DTO)에 자동으로 바인딩해 주는 대표적인 SQL 매퍼(SQL Mapper) 프레임워크.
- 데이터 접근 기술 3대 패러다임 비교

| **구분** | **JdbcTemplate** | **MyBatis** | **JPA / Spring Data** |
| --- | --- | --- | --- |
| 패러다임 | SQL 중심 직접 실행 | SQL 매퍼 (SQL Mapper) | 객체-관계 매핑 (ORM) |
| SQL 작성 위치 | 자바 소스코드 내부 문자열 | 독립된 XML 파일 또는 어노테이션 | 프레임워크가 자동 생성 |
| 동적 쿼리 제어 | 복잡한 문자열 결합(StringBuilder) | 풍부한 동적 XML 태그(`<if>`, `<choose>` 등) | Criteria API / Querydsl 컴파일 타임 검증 |
| 객체 매핑 방식 | RowMapper 수동 구현 필요 | XML resultMap 및 컬럼명 자동 매핑 | 엔티티 어노테이션 기반 자동 객체 매핑 |
| 주요 적합 분야 | 단순 관리자 도구, 배치 스크립트 1 | 복잡한 통계 쿼리, 기존 레거시 SQL 유지보수 | 도메인 주도 설계(DDD), 비즈니스 로직 중심 |

### **1.2 MyBatis의 핵심 역할과 자동화 메커니즘**

- SQL과 자바 코드의 완전한 분리
    - 복잡한 SQL 쿼리문을 자바 소스코드에 하드코딩하지 않고 독립된 XML 파일로 격리하여 관리함.
    - 쿼리 수정 시 자바 코드를 다시 컴파일하지 않고 XML 파일 수정만으로 대응할 수 있어 유지보수성이 향상됨.
- 인터페이스 선언 기반의 자동 실행
    - 개발자가 데이터베이스 연동을 위한 DAO 구현 클래스를 직접 만들지 않고, `@Mapper` 인터페이스에 메서드 시그니처만 선언함.
    - MyBatis가 인터페이스 메서드 호출을 감지하여 매퍼 XML에 정의된 동일한 ID의 SQL 쿼리를 자동으로 찾아 실행함.
- 파라미터 바인딩과 결과 객체(DTO) 자동 매핑
    - 자바 메서드로 전달한 DTO나 단일 파라미터를 SQL의 `#{}` 위치에 PreparedStatement 파라미터로 자동 바인딩함.
    - 데이터베이스에서 조회된 ResultSet 결과 데이터를 선언한 반환 타입(Record/DTO) 객체의 필드에 카멜 케이스 규칙에 맞추어 자동으로 조립하여 반환함.

## **2. MyBatis 핵심 구성 요소와 동작 원리**

### **2.1 MyBatis 개발 시 작성하는 핵심 파일의 종류와 역할**

- MyBatis 기반 데이터 접근 계층을 구현할 때 일반적으로 3가지 핵심 파일(DTO, Mapper 인터페이스, Mapper XML)을 세트로 구성함.

#### **1) 데이터 전송 객체 (Record / DTO)**

- DTO (Data Transfer Object)
    - 계층 간(데이터베이스 ↔ 데이터 접근 계층 ↔ 서비스 계층 ↔ 컨트롤러) 데이터 교환을 전담하는 순수 자바 객체.
    - 별도의 비즈니스 로직을 포함하지 않고 오직 전달할 데이터(필드)만을 캡슐화하여 전달하는 데이터 바구니 역할을 수행함.
- Record (Java 16+ 표준 불변 데이터 모델)
    - 불변(Immutable) 데이터를 간결하게 표현하기 위해 도입된 자바의 특수 클래스 선언 문법(class 선언 대신 record로 선언).
    - 선언만으로 모든 필드가 `private final`로 지정되며, 전체 매개변수 생성자, 필드명과 동일한 이름의 Getter 메서드, `equals()`, `hashCode()`, `toString()`이 컴파일러에 의해 자동 생성됨.
- 일반 클래스(POJO) DTO와 Record 선택 기준
    - Record 선택이 적합한 경우
        - 단순 단건 및 목록 조회 응답 DTO: 데이터베이스 조회 결과를 정규 생성자로 한 번에 바인딩하므로 불변성과 스레드 안전성을 확보하고 보일러플레이트 코드를 최소화함.
        - 검색 조건 파라미터 DTO: 여러 검색 조건을 읽기 전용으로 전달할 때 데이터 임의 변조를 사전에 방지함.
        - 1:1 조인 하위 객체 또는 1:N 컬렉션의 개별 원소 객체: `<constructor>` 태그를 통해 생성자 인자로 한 번에 주입받을 수 있음.
    - 일반 클래스(POJO/Lombok) 선택이 적합한 경우
        - 자동 생성 기본키(PK)를 주입받는 등록 DTO: MyBatis의 `useGeneratedKeys` 및 `keyProperty` 기능이 사후에 생성된 PK 값을 Setter(`setId()`)로 주입해야 하므로 가변 필드가 필요함.
        - 1:N 조인 쿼리의 최상위 결과 DTO: 여러 행(Row)으로 반환되는 조인 결과를 순회하며 컬렉션(`List`)에 하위 객체들을 점진적으로 누적 추가(`add`)해야 하므로 기본 생성자와 접근자가 열려 있는 클래스 구조가 필요함.
- 게시글 생성 요청 DTO (src/main/java/net/likelion/bebc25/sns/dto/PostCreateDto.java)

    ```java
    package net.likelion.bebc25.sns.dto;
    
    import lombok.AllArgsConstructor;
    import lombok.Builder;
    import lombok.Getter;
    import lombok.NoArgsConstructor;
    import lombok.Setter;
    
    @Getter
    @Setter
    @NoArgsConstructor
    @AllArgsConstructor
    @Builder
    public class PostCreateDto {
        private Long id;
        private Long memberId;
        private String content;
        private String imageUrl;
    
        public PostCreateDto(Long memberId, String content, String imageUrl) {
            this.memberId = memberId;
            this.content = content;
            this.imageUrl = imageUrl;
        }
    }
    ```

- 게시글 조회 응답 DTO (src/main/java/net/likelion/bebc25/sns/dto/PostResponseDto.java)

    ```java
    package net.likelion.bebc25.sns.dto;
    
    import java.time.LocalDateTime;
    
    public record PostResponseDto(
        Long id,
        Long memberId,
        String content,
        String imageUrl,
        LocalDateTime createdAt,
        LocalDateTime updatedAt
    ) {}
    ```


#### **2) 매퍼 인터페이스 (Mapper Interface)**

- `@Mapper` 어노테이션을 부여하고 SQL 실행 메서드의 시그니처만 선언하는 자바 인터페이스.
- 별도의 DAO 구현 클래스를 작성하지 않고 인터페이스 선언만으로 데이터베이스 연동이 가능함.
- PostMapper 인터페이스 (src/main/java/net/likelion/bebc25/sns/mapper/PostMapper.java)

    ```java
    package net.likelion.bebc25.sns.mapper;
    
    import net.likelion.bebc25.sns.dto.PostResponseDto;
    import org.apache.ibatis.annotations.Mapper;
    import org.apache.ibatis.annotations.Param;
    
    @Mapper
    public interface PostMapper {
    
        // ID 기반 게시글 단건 조회
        PostResponseDto findById(@Param("id") Long id);
    }
    ```


#### **3) 매퍼 XML 파일 (Mapper XML)**

- 실제 데이터베이스에서 실행할 SQL 쿼리문(`<select>`, `<insert>` 등)과 조회 결과(ResultSet)와 객체(DTO)를 매핑하는 규칙(단일 매핑 및 ResultMap 복합 조인 매핑)을 작성하는 XML 파일.
- 상단의 `<mapper namespace="...">` 속성에 매퍼 인터페이스의 전체 패키지 경로를 지정하고, 태그의 `id` 속성을 인터페이스 메서드명과 일치시켜서 작성.
- PostMapper.xml 파일 (src/main/resources/mapper/PostMapper.xml)

    ```xml
    <?xml version="1.0" encoding="UTF-8" ?>
    <!DOCTYPE mapper
      PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
      "https://mybatis.org/dtd/mybatis-3-mapper.dtd">
    
    <mapper namespace="net.likelion.bebc25.sns.mapper.PostMapper">
    
      <select id="findById" parameterType="long" resultType="PostResponseDto">
        SELECT id, member_id, content, image_url, created_at, updated_at
        FROM post
        WHERE id = #{id}
      </select>
    
    </mapper>
    ```


#### **4) 개발 흐름 및 파일 간의 유기적 상호작용**

- 1단계 (DTO 정의): 데이터베이스 테이블 컬럼 구조에 맞추어 요청/응답용 Record DTO를 정의함.
- 2단계 (Mapper 인터페이스 선언): 서비스 계층에서 호출할 메서드명과 반환 타입을 `@Mapper` 인터페이스에 선언함.
- 3단계 (Mapper XML 작성): XML 상단의 `<mapper namespace="...">`에 매퍼 인터페이스의 전체 패키지 경로를 지정하고, 인터페이스 메서드명과 동일한 `id` 값을 가진 태그(`<select id="...">`)를 작성하여 SQL을 매핑함.

### **2.2 Mapper 인터페이스의 내부 동작 원리와 동적 프록시**

- MyBatis 3대 핵심 컴포넌트
    - SqlSessionFactory: 설정 정보와 매퍼 XML을 파싱하여 애플리케이션 시작 시점에 생성되는 싱글톤 팩토리 객체.
    - SqlSession: SQL 실행 및 트랜잭션 제어를 담당하는 핵심 인터페이스.
    - SqlSessionTemplate: 스프링 부트 환경에서 스프링 트랜잭션 매니저와 연동되어 멀티스레드 환경에서도 안전하게 싱글톤으로 공유되는 SqlSession 구현체.

#### **1) 스프링 부트 기동 시점: 자동 구성에 의한 빈 조립 과정**

- 스프링 부트 애플리케이션이 시작될 때 `mybatis-spring-boot-starter`의 자동 구성(Auto-Configuration) 모듈이 동작하여 핵심 객체들을 순차적으로 생성하고 스프링 컨테이너에 등록함.

```
[application.yml 설정] + [DataSource 커넥션 풀]
                        │
                        ▼ (1) 설정과 커넥션 풀을 기반으로 싱글톤 생성
               [SqlSessionFactory]
                        │
                        ▼ (2) 트랜잭션 연동 및 멀티스레드 안전성 보장을 위해 래핑
              [SqlSessionTemplate]
                        │
                        ▼ (3) @Mapper 인터페이스를 스캔하여 프록시 생성 및 주입
        [@Mapper 동적 프록시 Bean (PostMapper)]
```

- @Mapper 인터페이스 스캔과 동적 프록시 3 생성
    - 개발자가 별도의 DAO 구현 클래스를 작성하지 않아도, 프레임워크가 인터페이스를 기반으로 런타임에 동적 프록시 객체를 자동 생성함.
    - 생성된 동적 프록시 객체 내부에 `SqlSessionTemplate`을 탑재하여 서비스 계층에 스프링 빈으로 주입함.

#### **2) 런타임 실행 시점: 쿼리 실행 및 결과 반환 위임 흐름**

- 서비스 계층에서 매퍼 인터페이스의 메서드를 호출했을 때 실제 내부에서 처리되는 단계별 위임 메커니즘.

```
[1. Service 계층] ──> postMapper.findById(1L) 호출
                             │
                             ▼ (호출 가로챔)
[2. 동적 프록시 Bean] ──> MapperProxy가 메서드명과 매퍼 XML의 SQL 태그 ID를 연결
                             │
                             ▼ (실행 위임)
[3. SqlSessionTemplate] ──> 스프링 트랜잭션 동기화 저장소에서 현재 DB 커넥션 획득
                             │
                             ▼ (쿼리 실행)
[4. 매퍼 XML SQL]   ──> PreparedStatement 바인딩 후 SELECT 쿼리 수행
                             │
                             ▼ (결과 변환)
[5. DB ResultSet]   ──> PostResponseDto 객체 필드로 자동 매핑 후 Service에 최종 반환
```

## **3. MyBatis 빌드 의존성 및 환경 설정**

### **1.3.1 빌드 의존성 설정 (build.gradle)**

- 스프링 부트에서 MyBatis를 사용하기 위해 `mybatis-spring-boot-starter`와 데이터베이스 연동 드라이버(예: `mysql-connector-j`)를 의존성에 추가.

    ```
    dependencies {
        ...
        // MyBatis Spring Boot Starter
        implementation 'org.mybatis.spring.boot:mybatis-spring-boot-starter:4.0.1'
        // MySQL JDBC Driver
        runtimeOnly 'com.mysql:mysql-connector-j'
    }
    ```


### **1.3.2 스프링 부트 환경 설정 (application.yml)**

- MyBatis의 핵심 동작(XML 위치, DTO 별칭 패키지, 카멜 케이스 변환, SQL 로그 출력 등)을 선언함.

    ```yaml
    mybatis:
      # 1. MyBatis 매퍼 XML 파일 위치 지정 (경로 패턴)
      mapper-locations: classpath:mapper/**/*.xml
    
      # 2. DTO 패키지 별칭 지정 (XML에서 패키지 경로 생략 가능)
      type-aliases-package: net.likelion.bebc25.sns.dto
    
      configuration:
        # 3. DB 스네이크 케이스 컬럼명을 자바 카멜 케이스 필드명으로 자동 매핑
        map-underscore-to-camel-case: true
    
        # 4. 콘솔에 실행 SQL 및 파라미터 바인딩 로그 출력 (개발/디버깅용)
        log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
    ```


## **4. Mapper 인터페이스와 매개변수 바인딩**

### **4.1 @Param 어노테이션 활용 기준**

- 단일 DTO / Record 객체를 전달할 때
    - `@Param`을 생략하고 넘기는 것이 표준 관례이며, XML에서는 DTO 내부 필드명을 `#{content}`, `#{imageUrl}` 형태로 직접 꺼내어 사용함.
    - 만약 단일 DTO 앞에 `@Param("post")`를 부여하면 XML에서도 반드시 `#{post.content}`, `#{post.imageUrl}`처럼 지정한 별칭을 접두어로 붙여서 접근해야 함.
    - DTO와 단일 값(예: `memberId`)을 동시에 넘길 때는 이름 충돌을 방지하기 위해 DTO 앞에도 `@Param("post")`를 선언하며, XML에서는 `#{memberId}`와 `#{post.content}`로 구분하여 바인딩함.
- 단일 기본형/문자열 파라미터를 전달할 때
    - 단일 값은 `@Param`이 없어도 XML의 `#{}`에 들어오는 값이 자동으로 1:1 매핑되지만, 코드의 가독성과 명확성을 위해 `@Param("id") Long id` 형태로 명시하는 것을 권장함.
- 2개 이상의 매개변수 또는 컬렉션(List, Set)을 전달할 때
    - 자바 컴파일러의 매개변수 이름 소실 문제를 방지하고 XML과의 정확한 바인딩을 위해 반드시 `@Param("keyword")`, `@Param("memberId")`, `@Param("idList")`처럼 파라미터 이름을 선언해야 함.

### **4.2 매개변수 바인딩 문법: `#{}` vs `${}`**

- `#{}` (PreparedStatement 바인딩)
    - 파라미터 값이 SQL 문장에 물음표(?) 파라미터로 치환되어 전달되므로 값에 따옴표가 자동 부착되고 SQL Injection 4 공격을 방지함.
    - 일반적인 모든 데이터 조건 조회, 등록, 수정, 삭제 시 필수적으로 사용함.
- `${}` (문자열 직접 치환)
    - 파라미터 값이 SQL 문장에 따옴표 없이 그대로 치환되어 삽입됨.
    - 사용자 입력값을 그대로 넣을 경우 SQL Injection 취약점이 발생하므로, 동적 테이블명이나 정렬 컬럼명(`ORDER BY ${sortColumn}`)을 안전하게 지정할 때를 제외하고는 사용을 지양.

| --- | --- | --- |
| `id` | 전체 (`select`, `insert`, `update`, `delete`) | 매퍼 인터페이스의 메서드명과 1:1 매핑되는 고유 식별자. |
| `parameterType` | 전체 | SQL 문에 전달되는 파라미터의 자바 타입(패키지 경로 또는 별칭). (생략 가능) |

| `keyProperty` | `insert`, `update` | `useGeneratedKeys="true"`로 가져온 자동 생성 PK 값을 파라미터 객체의 어떤 필드에 세팅할지 지정 (예: `keyProperty="id"`). |

### **5.1 1:1 계층적 복합 객체 매핑 (`<resultMap>`)**

- 여러 테이블을 조인(JOIN)하여 계층적 복합 객체(1:1 단일 객체 매핑, 1:N 컬렉션 매핑)를 조립할 때는 `<resultMap>` 태그를 사용함.
- 매퍼 XML (src/main/resources/mapper/PostMapper.xml)

    ```xml
    <mapper namespace="net.likelion.bebc25.sns.mapper.PostMapper">
    
      ...
    
      <!-- 3개 테이블 조인 쿼리 -->
      <select id="findPostDetailById" parameterType="long" resultMap="PostDetailResultMap">
        SELECT
          p.id AS post_id,
          p.content AS post_content,
          p.image_url AS post_image_url,
          p.created_at AS post_created_at,
          m.id AS member_id,
          m.nickname AS member_nickname,
          m.profile_image AS member_profile_image,
          c.id AS comment_id,
          c.member_id AS commenter_id,
          cm.nickname AS commenter_nickname,
          c.content AS comment_content,
          c.created_at AS comment_created_at
        FROM post p
        INNER JOIN member m ON p.member_id = m.id
        LEFT JOIN comment c ON p.id = c.post_id
        LEFT JOIN member cm ON c.member_id = cm.id
        WHERE p.id = #{id}
        ORDER BY c.id ASC
      </select>
    
      <resultMap id="PostDetailResultMap" type="PostDetailResponseDto">
        <id property="id" column="post_id" />
        <result property="content" column="post_content" />
        <result property="imageUrl" column="post_image_url" />
        <result property="createdAt" column="post_created_at" />
    
        <!-- 작성자 회원 정보 1:1 매핑 (<association>) -->
    
        <!-- 댓글 목록 1:N 매핑 (<collection>) -->
    
      </resultMap>
    
    </mapper>
    ```

    - `<resultMap>` 태그 속성
        - `id`: 해당 ResultMap의 고유 식별자 이름으로, `<select resultMap="...">`에서 지정하여 매핑 규칙을 적용함.
        - `type`: 최종적으로 조립된 결과 데이터를 담아 반환할 최상위 자바 DTO 객체 타입 (예: `PostDetailResponseDto`).
    - `<resultMap>` 내부 매핑 태그 및 속성
        - `<id>`: 기본키(PK, 식별자) 컬럼 매핑 태그. 객체 인스턴스의 고유성을 식별하여 조인 시 중복 객체 생성을 방지하고 메모리 조립 성능을 최적화함.
        - `<result>`: 기본키 이외의 일반 데이터 컬럼과 DTO 필드를 1:1 매핑하는 태그.
        - `property`: 컬럼 데이터가 매핑되어 저장될 자바 DTO 객체의 실제 필드명.
        - `column`: SELECT 조회 결과의 데이터베이스 컬럼명 또는 AS 별칭.
- PostMapper 인터페이스 메서드 추가 (src/main/java/net/likelion/bebc25/sns/mapper/PostMapper.java)

    ```java

    PostDetailResponseDto findPostDetailById(Long id);
    ```

### **5.2 1:1 단일 객체 매핑 (`<association>`)**

- 게시글 상세 조회 시 게시글(`post`) 정보에 작성자(`member`)의 요약 정보(`id`, `nickname`, `profileImage`)를 함께 조립하여 반환할 때 `<association>` 태그를 사용함.
- `MemberResponseDto`가 불변 `record`인 경우 Setter가 존재하지 않으므로, `<constructor>` 태그와 `<idArg>`, `<arg>`를 사용하여 정규 생성자 인자에 컬럼 값을 매핑함.
- `<association>` 태그 속성
    - `property`: 상위 DTO 내 필드명을 지정함.
    - `javaType`: 1:1로 매핑되는 단일 하위 객체의 자바 Record 타입 (예: `MemberResponseDto`).
- 작성자 1:1 매핑 XML (src/main/resources/mapper/PostMapper.xml)

    ```xml
    <!-- 작성자 회원 정보 1:1 매핑 (<association>) -->
    <association property="author" javaType="MemberResponseDto">
      <constructor>
        <idArg column="member_id" javaType="Long" />
        <arg column="member_nickname" javaType="String" />
        <arg column="member_profile_image" javaType="String" />
      </constructor>
    </association>
    ```


### **5.3 1:N 컬렉션 매핑 (`<collection>`)**

- 하나의 게시글에 달린 여러 개의 댓글 목록(`List<CommentResponseDto>`)을 한 번의 쿼리로 함께 매핑할 때 `<collection>` 태그를 사용함.
- 컬렉션 원소인 `CommentResponseDto`가 불변 `record`인 경우 `<constructor>` 태그를 통해 생성자 인자 순서와 타입에 맞추어 매핑함.
- `<collection>` 태그 속성
    - `property`: 상위 DTO 내 리스트 필드명을 지정함.
    - `ofType`: 1:N으로 매핑되는 컬렉션(List)의 개별 원소로 들어갈 자바 Record 타입.
    - `javaType`: 컬렉션을 담아둘 자바 컬렉션 구현체 타입 (예: `ArrayList`).
- 댓글 목록 1:N 매핑 XML (src/main/resources/mapper/PostMapper.xml)

    ```xml
    <!-- 댓글 목록 1:N 매핑 (<collection>) -->
    <collection property="comments" ofType="CommentResponseDto" javaType="ArrayList">
      <constructor>
        <idArg column="comment_id" javaType="Long" />
        <arg column="commenter_id" javaType="Long" />
        <arg column="commenter_nickname" javaType="String" />
        <arg column="comment_content" javaType="String" />
        <arg column="comment_created_at" javaType="java.time.LocalDateTime" />
      </constructor>
    </collection>
    ```

## **6. 동적 SQL 제어와 공통 쿼리 모듈화**

- 검색 조건 DTO (src/main/java/net/likelion/bebc25/sns/dto/PostSearchCondition.java)

- PostMapper 인터페이스 메서드 선언 (src/main/java/net/likelion/bebc25/sns/mapper/PostMapper.java)

### **6.1 `<where>`와 `<if>` 태그를 활용한 다중 조건 검색**

- 검색 조건 DTO(`PostSearchCondition`)에 담긴 필드 값의 존재 유무에 따라 WHERE 절을 유연하게 생성함.
- `<where>` 태그는 조건문이 하나라도 참일 때만 `WHERE` 키워드를 삽입하고, 조건문 맨 앞에 오는 불필요한 `AND`나 `OR` 키워드를 자동으로 제거함.

    ```xml
    <!-- 다중 조건 동적 검색 쿼리 -->
    <select id="searchPosts" parameterType="PostSearchCondition" resultType="PostResponseDto">
        SELECT id, member_id, content, image_url, created_at, updated_at
        FROM post
        <where>
            <if test="keyword != null and keyword != ''">
                AND content LIKE CONCAT('%', #{keyword}, '%')
            </if>
            <if test="memberId != null">
                AND member_id = #{memberId}
            </if>
            <if test="targetMemberIds != null and !targetMemberIds.isEmpty()">
                AND member_id IN
                <foreach item="targetId" collection="targetMemberIds" open="(" separator="," close=")">
                    #{targetId}
                </foreach>
            </if>
        </where>
        ORDER BY id DESC
    </select>
    ```


### **6.2 `<choose>`, `<when>`, `<otherwise>`를 활용한 동적 정렬 분기**

- 자바의 switch-case 문처럼 전달받은 `sortOrder` 값에 따라 ORDER BY 정렬 기준을 안전하게 분기함.

    ```xml
    <!-- 동적 정렬 분기 조회 -->
    <select id="findPostsWithSort" parameterType="PostSearchCondition" resultType="PostResponseDto">
        SELECT id, member_id, content, image_url, created_at, updated_at
        FROM post
        <choose>
            <when test="sortOrder == 'POPULAR'">
                ORDER BY like_count DESC, id DESC
            </when>
            <otherwise>
                ORDER BY id DESC
            </otherwise>
        </choose>
    </select>
    ```


### **6.3 `<set>` 태그를 활용한 동적 부분 수정 (Dynamic UPDATE)**

- 수정이 요청된 필드만 선택적으로 UPDATE하며, 마지막 컬럼 뒤에 남는 불필요한 쉼표(,)를 자동으로 제거해 줌.

    ```xml
    <!-- 동적 부분 수정 (Dynamic UPDATE) -->
    <update id="updateSelective" parameterType="map">
        UPDATE post
        <set>
            <if test="content != null">
                content = #{content},
            </if>
            <if test="imageUrl != null">
                image_url = #{imageUrl},
            </if>
            updated_at = NOW()
        </set>
        WHERE id = #{id}
    </update>
    ```


### **6.4 `<foreach>` 태그를 활용한 컬렉션 반복 (IN 절 및 일괄 삭제)**

- List, Set 등의 컬렉션을 반복 순회하여 `IN (1, 2, 3)` 형태의 SQL 절을 동적으로 생성함.

    ```xml
    <!-- 다중 ID 일괄 삭제 (동적 foreach) -->
    <delete id="deleteByIds">
        DELETE FROM post
        WHERE id IN
        <foreach item="targetId" collection="idList" open="(" separator="," close=")">
            #{targetId}
        </foreach>
    </delete>
    ```


### **6.5 `<sql>`과 `<include>` 태그를 활용한 쿼리 조각 재사용**

- 자주 중복되는 컬럼 목록이나 공통 조건절을 `<sql id="...">`로 정의하고, 필요한 곳에서 `<include refid="...">`로 재사용하여 유지보수성을 높임.

    ```xml
    <!-- 공통 컬럼 조각 정의 -->
    <sql id="postColumns">
        id, member_id, content, image_url, created_at, updated_at
    </sql>
    
    <!-- 공통 조각 재사용 -->
    <select id="findByIdWithInclude" parameterType="long" resultType="PostResponseDto">
        SELECT <include refid="postColumns" />
        FROM post
        WHERE id = #{id}
    </select>
    ```

```java
package net.likelion.bebc25.sns.mapper;

import net.likelion.bebc25.sns.dto.PostCreateDto;
import net.likelion.bebc25.sns.dto.PostResponseDto;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;

import java.util.List;

@Mapper
public interface PostMapper {

    // 게시글 전체 목록 조회
    List<PostResponseDto> findAll();

    // ID 기반 게시글 단건 조회
    PostResponseDto findById(@Param("id") Long id);

    // 작성자 ID 기반 게시글 목록 조회
    List<PostResponseDto> findByMemberId(@Param("memberId") Long memberId);

    // 신규 게시글 등록 (Auto Increment ID 자동 바인딩)
    void save(PostCreateDto post);

    // 게시글 본문 및 이미지 수정
    void update(@Param("id") Long id, @Param("content") String content, @Param("imageUrl") String imageUrl);

    // 게시글 단건 삭제
    void deleteById(Long id);
}
```

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "https://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="net.likelion.bebc25.sns.mapper.PostMapper">

    <!-- 공통 컬럼 SQL 조각 -->
    <sql id="postColumns">
        id, member_id, content, image_url, created_at, updated_at
    </sql>

    <!-- 1. 전체 목록 조회 -->
    <select id="findAll" resultType="PostResponseDto">
        SELECT <include refid="postColumns" />
        FROM post
        ORDER BY id DESC
    </select>

    <!-- 2. ID 기반 단건 상세 조회 -->
    <select id="findById" parameterType="long" resultType="PostResponseDto">
        SELECT <include refid="postColumns" />
        FROM post
        WHERE id = #{id}
    </select>

    <!-- 3. 작성자 ID 기반 목록 조회 -->
    <select id="findByMemberId" parameterType="long" resultType="PostResponseDto">
        SELECT <include refid="postColumns" />
        FROM post
        WHERE member_id = #{memberId}
        ORDER BY id DESC
        LIMIT 10
    </select>

    <!-- 4. 신규 게시글 등록 (자동 생성 PK 바인딩) -->
    <insert id="save" parameterType="PostCreateDto" useGeneratedKeys="true" keyProperty="id">
        INSERT INTO post (member_id, content, image_url, created_at, updated_at)
        VALUES (#{memberId}, #{content}, #{imageUrl}, NOW(), NOW())
    </insert>

    <!-- 5. 게시글 수정 -->
    <update id="update">
        UPDATE post
        SET content = #{content},
            image_url = #{imageUrl},
            updated_at = NOW()
        WHERE id = #{id}
    </update>

    <!-- 6. 단건 삭제 -->
    <delete id="deleteById" parameterType="long">
        DELETE FROM post
        WHERE id = #{id}
    </delete>

</mapper>
```

### **3.3 매퍼 XML에 ResultMap 및 3중 조인 쿼리 추가**

- PostMapper.xml에 ResultMap 및 조인 쿼리 추가 (src/main/resources/mapper/PostMapper.xml)

```xml
    <!-- ResultMap 복합 객체 조립 정의 (1:1 작성자, 1:N 댓글 목록) -->
    <resultMap id="PostDetailResultMap" type="PostDetailResponseDto">
        <id property="id" column="post_id" />
        <result property="content" column="post_content" />
        <result property="imageUrl" column="post_image_url" />
        <result property="createdAt" column="post_created_at" />

        <!-- 작성자 회원 정보 1:1 매핑 -->
        <association property="author" javaType="MemberResponseDto">
            <constructor>
                <idArg column="member_id" javaType="Long" />
                <arg column="member_nickname" javaType="String" />
                <arg column="member_profile_image" javaType="String" />
            </constructor>
        </association>

        <!-- 댓글 목록 1:N 매핑 -->
        <collection property="comments" ofType="CommentResponseDto" javaType="ArrayList">
            <constructor>
                <idArg column="comment_id" javaType="Long" />
                <arg column="commenter_id" javaType="Long" />
                <arg column="commenter_nickname" javaType="String" />
                <arg column="comment_content" javaType="String" />
                <arg column="comment_created_at" javaType="java.time.LocalDateTime" />
            </constructor>
        </collection>
    </resultMap>

    <!-- 게시글 상세 + 작성자 + 댓글 3중 조인 쿼리 -->
    <select id="findPostDetailById" parameterType="long" resultMap="PostDetailResultMap">
        SELECT
            p.id AS post_id,
            p.content AS post_content,
            p.image_url AS post_image_url,
            p.created_at AS post_created_at,
            m.id AS member_id,
            m.nickname AS member_nickname,
            m.profile_image AS member_profile_image,
            c.id AS comment_id,
            c.member_id AS commenter_id,
            cm.nickname AS commenter_nickname,
            c.content AS comment_content,
            c.created_at AS comment_created_at
        FROM post p
        INNER JOIN member m ON p.member_id = m.id
        LEFT JOIN comment c ON p.id = c.post_id
        LEFT JOIN member cm ON c.member_id = cm.id
        WHERE p.id = #{id}
        ORDER BY c.id ASC
    </select>
```

    ```xml
    <!-- 다중 조건 동적 검색 및 정렬 쿼리 -->
    <select id="searchPosts" parameterType="PostSearchCondition" resultType="PostResponseDto">
        SELECT <include refid="postColumns" />
        FROM post
        <where>
            <if test="keyword != null and keyword != ''">
                AND content LIKE CONCAT('%', #{keyword}, '%')
            </if>
            <if test="memberId != null">
                AND member_id = #{memberId}
            </if>
            <if test="targetMemberIds != null and !targetMemberIds.isEmpty()">
                AND member_id IN
                <foreach item="targetId" collection="targetMemberIds" open="(" separator="," close=")">
                    #{targetId}
                </foreach>
            </if>
        </where>
        <choose>
            <when test="sortOrder == 'POPULAR'">
                ORDER BY like_count DESC, id DESC
            </when>
            <otherwise>
                ORDER BY id DESC
            </otherwise>
        </choose>
    </select>
    
    <!-- 다중 ID 일괄 삭제 (동적 foreach) -->
    <delete id="deleteByIds">
        DELETE FROM post
        WHERE id IN
        <foreach item="targetId" collection="idList" open="(" separator="," close=")">
            #{targetId}
        </foreach>
    </delete>
    ```

## **5. @MybatisTest 슬라이스 테스트 적용 가이드**

### **5.1 @MybatisTest의 특징 및 작동 방식**

- 전체 스프링 컨텍스트를 로드하지 않고, `DataSource`, `SqlSessionFactory`, `@Mapper` 인터페이스 등 MyBatis 연동에 필요한 최소 컴포넌트만 선별 로딩하여 테스트 실행 속도를 단축함.
- `@MybatisTest` 어노테이션 내부에 `@Transactional`이 기본 포함되어 있어 별도 선언 없이도 테스트 종료 후 자동 롤백을 지원함.

### **5.2 MySQL 연동을 위한 테스트 데이터베이스 설정**

- `@MybatisTest`는 기본 동작으로 H2와 같은 임베디드 인메모리 데이터베이스를 탐색함.
- 실제 프로젝트의 MySQL(`sns_db`) 접속 정보(`application.yml`)를 그대로 사용하여 쿼리를 검증하려면 `@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE)` 옵션을 함께 선언해야 함.
- `@MybatisTest` 적용 예시 (src/test/java/net/likelion/bebc25/sns/mapper/PostMapperSliceTest.java)

    ```java
    package net.likelion.bebc25.sns.mapper;

    import org.springframework.beans.factory.annotation.Autowired;
    import org.springframework.boot.jdbc.test.autoconfigure.AutoConfigureTestDatabase;
    
    import java.util.List;
    
    import static org.assertj.core.api.Assertions.assertThat;
    
    @MybatisTest
    @AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE) // 실제 MySQL DataSource 사용

        private PostMapper postMapper;

            // given

        }
    }
    ```
